# Direct Codex control of VIAVW

Codex operated installed Word, VLC and 7-Zip through this interface on October 22, 2026. This path does not require modifying CharlieAI or installing a network service. It is a project-owned console that retains the existing VIAVW host across separate tool calls.

Start it in one persistent command session, with terminal input kept available:

```powershell
& "C:\Programming\Projects\VIAVW\scripts\start-viavw-console.ps1"
```

For Codex's command tool, use a persistent terminal session (`tty:true`) and send subsequent JSON lines to that same session with its input tool. Do not start a new console for every action. The launcher selects the hash-checked experimental build in `artifacts/installed-apps-current.json`; the ordinary Visual Studio/API launchers retain their accepted executable selections.

The console prints a readiness object. Each command requires its own `id`; each reply has `id`, `ok` and either `data` or `error`. Standard output is JSON lines; terminal echo/formatting is outside the protocol. `--compact` is used by the launcher: observations print their state, paths and token, while the complete response is retained under `console-responses`. `console-timings.jsonl` records request IDs and durations without logging typed input. Response artifacts can contain application titles/control state and should be treated as local application data.

## Inspect → act → verify

Create Word using a **disposable existing file**, `/a`, and the demonstrated print capture option. Replace the example path with the actual fixture generated by the demo/preparation script.

```json
{"id":"create-1","op":"create","launch":{"executable":"C:\\Program Files\\Microsoft Office\\root\\Office16\\WINWORD.EXE","arguments":["/a","C:\\Programming\\Projects\\VIAVW\\artifacts\\YOUR_FIXTURE\\word-first.rtf"],"captureMode":"print-window"}}
{"id":"inspect-1","op":"observe","session":"RETURNED_SESSION","capture":true,"accessibility":true}
```

Read the actual PNG with the local image tool. Read the full-response/accessibility files when needed; those paths refer to that console's owned applications. Do not use physical keyboard/mouse injection or the physical desktop browser to operate the source app. `ready` only establishes an owned window; a splash window can precede its document. Wait for the actual document title/control before editing.

Use the returned `observationId` for input. Target the appropriate owned **child HWND** for editor clicks. A point in the root image may need conversion to child-client coordinates; accessibility rectangles are screen coordinates, while `sourceClientOrigin` is the root image's origin. Inspect geometry rather than guessing across surfaces.

```json
{"id":"click-1","op":"input","observationId":"RETURNED_OBSERVATION","kind":"click","fields":{"window":123456,"x":750,"y":143,"deliveryMode":"posted"}}
{"id":"type-1","op":"input","observationId":"RETURNED_OBSERVATION","kind":"text","fields":{"text":"Disposable text"}}
{"id":"save-1","op":"input","observationId":"RETURNED_OBSERVATION","kind":"chord","fields":{"keys":[17,83]}}
{"id":"inspect-2","op":"observe","session":"RETURNED_SESSION","capture":true}
```

The input kinds are text/key/chord/click. `deliveryMode:"posted"` is an explicit experimental click option that avoided the tested 7-Zip synchronous list-control timeout. Default synchronous clicks remain available. Neither delivery mode proves application completion. Use separate real Enter/Backspace keys. Verify the application result or saved file before proceeding. In particular, do not send a blind chain of dialog navigation shortcuts: Word's Save As keyboard attempt selected an unintended disposable filename. Inspection and explicit mouse targets recovered the workflow.

Read-only `no_surface`/`observation_changed` during a transition may justify another observation. An input error/timeout must not be replayed automatically. It pauses the workspace; a fresh context-checked `resume` is required. The console remembers exact command lines for deduplication: repeating a cached ID returns the historical response, conflicting payloads are rejected, and expired responses never cause input replay. It retains 32 replies, 128 observation tokens and at most 4000 ordinary command IDs; underlying host budgets also apply.

## Windows, ownership and lifetime

An application such as Word can open multiple document windows in the same session. Observe its owned windows, then select the intended top-level HWND:

```json
{"id":"select-1","op":"surface","observationId":"RETURNED_OBSERVATION","window":123456}
{"id":"inspect-selected","op":"observe","session":"RETURNED_SESSION","capture":true,"accessibility":true}
```

Selection checks ownership/revision, rejects foreign windows and invalidates that session's old console observation tokens. Selecting a window does not physically activate it. The fresh observation may select an owned modal rather than its disabled parent. Automatic splash replacement only accepts one unambiguous titled top-level window in the same application PID; ambiguity stops input rather than guessing.

```json
{"id":"human-1","op":"human","observationId":"RETURNED_OBSERVATION","reason":"Please inspect or edit this document"}
{"id":"status-1","op":"status","session":"RETURNED_SESSION"}
{"id":"resume-1","op":"resume","session":"RETURNED_SESSION","context":{"rootTitle":"EXACT_INSPECTED_TITLE","rootClass":"OpusApp"}}
```

`human` opens the viewer without activation and gives Human ownership. Old plans are invalidated. Keep the console alive throughout the user's turn. The user selects **Return to automation** in the viewer; `resume` never reclaims ownership. Inspect their actual edits before deciding what to do next. The resume title/class predicate is conservative identity checking, not a general semantic-readiness oracle. An always-true context assumption is not a substitute for inspecting the document/dialog.

`viewer` takes `session` and `visible`; `status`, `list`, `hello` are read operations. `close` takes a session and optional explicit `force:true`. `shutdown` gracefully closes all sessions and then the host; pending native prompts keep the console open. Explicit `shutdown` with `force:true` discards unsaved owned state. **EOF, terminal termination or a host crash still closes owned application jobs and can lose unsaved state.** Routine command errors keep the console alive. There is no detach/reconnect or crash-state recovery claim.

## Fast passive inspection (research build Apps-20261022l)

Use separate start/check commands when detailed control text is needed. These operations are advertised by the research host; the accepted `Agent-20261021l` host does not implement them.

```json
{"id":"scan-start","op":"inspect-begin","session":"SESSION"}
{"id":"scan-check","op":"inspect-poll","session":"SESSION","ticket":1}
```

Use the ticket returned in `data.result.ticket`, not the illustrative number above. An optional `automationId` on `inspect-begin` narrows the read (for example `WpfTextView` for the demonstrated VS editor). There is one pending scan per layer and at most 32 retained tickets. Starting another scan while one is pending returns `inspection_busy`; polling uses a fresh request ID. Exact duplicate IDs still return historical responses, so repeating a poll ID cannot obtain newer state.

Poll results contain `data.result.inspection` with `status` (`pending`, `partial`, `complete`, `timed_out`, `failed`, `cancelled`), sampled `result`, elapsed time and helper PID. `data.result.stale` becomes true after input, ownership or selected-surface changes. Partial/old results do not establish completion of an action. No scan automatically retries input. Re-observe actual application state before deciding another action.

The passive helper uses a separate kill-on-close job on the same private desktop and validates owned process IDs/desktop before UIA access. Its 750 ms provider deadline stops only that helper. Cold connection has a separate 1500 ms deadline; both run in the background. A completed healthy helper is reused and performs no continuous scan while idle. The owning host closing still ends its application sessions as documented above.

The older `observe` with `accessibility:true` now samples this helper for at most 100 ms **per accessibility query**, returning incomplete evidence when unfinished and withholding nodes after input/ownership changes. A full observe can also capture pixels and query multiple surfaces; 100 ms is not an end-to-end observation guarantee. Other capture/input/provider-assisted pointer paths still have their existing deadlines and containment behavior. This experiment specifically isolates passive tree/menu reads; it does not promise universal crash-safe input or foreground-native latency.
